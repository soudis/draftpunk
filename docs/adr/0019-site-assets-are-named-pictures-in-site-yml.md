# A picture of the whole site is a site asset: a name in site.yml that templates and styles use by name

The design may not hold a picture address (0013), and a picture slot belongs to one page, so a logo had no place: the first real setup could not put the logo into the menu. Now `site.yml` has `assets`, a map from a name (logo, favicon, social, hero-pattern) to a picture in `/media/`. Templates show one with `{{ assets.logo }}`, styles with `var(--asset-logo)` (the generator writes the properties), so no design file holds an address. The starter header shows `assets.logo` in place of the site name when it is set; the generator adds `favicon` and `social` to every page head. The agent sets one with `set_asset` after `save_picture` (and `fit_picture` for a logo), the guard's refusal says so, and a setup from a source site takes the site's logo and icon.

Rejected: two fixed fields (`logo`, `favicon`), which would not cover a texture or a background photo; and relaxing the guard for pictures in the shell, which would let page pictures into the design and break the rule that a design change leaves every page's content alone. The price is one more place for pictures: the media library holds the file, `site.yml` names it, and a picture that an asset names must stay (`check_design` says when it is gone).
