# The generator and the server add what a site needs, so that old sites get it too

A site's design (shell, layouts, styles) is its own: the agent edits it, so a change to the starter reaches only sites made afterwards. Most of what makes a site good is therefore done by the generator or by the server that sends the files, which every site passes through on each run, and not by the starter:

- **Pictures**: a picture in a page gets `srcset` and `sizes` (480, 960, 1600 px WebP, made with sharp in a child process, kept by file, time and size in the site's `.git` folder, which git does not track) and its `src` becomes the largest copy when the original is much wider. A picture under 40 KB, a GIF or an SVG is left alone. The copies live in `media/_sizes/` and are never changed under their name.
- **Alt text**: an empty or missing `alt` is filled from `media/pictures.yml` (`alt` per language, else the description), unless the picture is marked `decorative`. The page can still say what it wants. The generator reports the pictures that stay empty, and `check_site` shows them.
- **Head and structure**: description from the page's first paragraph when its layout names no slot for one, the site name not repeated in a title, `BreadcrumbList` data, `lastmod` in the sitemap (the day the content file changed), a 404 page per language, and the stylesheet named by its content.
- **Server**: one address per page (`/kontakt` goes to `/kontakt/`, not the other way), the 404 page for an unknown address, brotli or gzip with a validator, `nosniff`, referrer and permissions headers, and a content-security-policy that allows only the site itself and the page's own inline scripts by hash (nothing from another host is allowed by 0015 anyway). Files named by content and the picture copies are cached for a year.

The parts that are template (the header search field, the visible trail) cannot be put into a design that is the site's own. `upgradeDesign` adds only what is missing and never writes over a file: a generated layout the site lacks and the labels it needs. For a change to the shell it gives advice with the starter's lines, which `check_site` hands to the agent, who offers it to the person.

Rejected: rewriting the shell of an existing site (it would undo the agent's and the person's work), and a version number with migrations (more to keep than the few additions need). Cost: the child process makes the first run of a site with many large pictures take a minute; after that a run costs nothing for the pictures. A content-security-policy by script hash breaks a design that adds an inline event handler, such as `onclick`; the design lint should say so (not built).
