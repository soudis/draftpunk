# Layouts are site-owned folders with typed slots, and a page is one file of slot values

A layout is a folder in the site's design: `layout.yml` (a one-line purpose and a typed slot schema), `template.njk` (markup that shows slots and labels) and `style.css` (styles for that layout only, nested under the layout's name). A page is one file, `content/pages/<slug>.yml`, with its layout, its date, a title per language, and slot values; translated text holds one entry per language, and pictures and links are stored once. The generator checks a page against its layout's schema, so the page's content shape is whatever its layout declares.

The agent may create a layout for one page. Nothing limits how many layouts a site has. What the code enforces is the separation: a template holds no visible words of its own (text comes from slots or from `design/labels.yml`), no page names, no picture addresses; and a design change must leave every slot value on its page. A catalog of layouts (name, purpose, slot signature, pages that use it) goes into the agent's context so it reuses or forks a layout before it writes a new one.

This replaces the closed set of section shapes (0008), the split between section-list layouts and private templates (0010), the fixed front-matter fields of the home, room, gallery and allies layouts (0005), and per-language page files. A new section shape is no longer a change to this software. Nothing needs to stay compatible, because no site is in production. Reusable sections shared by several layouts come after the layouts and slots work.
