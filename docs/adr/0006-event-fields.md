# Event fields stay in the design

An event may have several fields. The design owns each field and its closed list of options. An option has an id, a German label, and an English label, and the event stores the id. Content picks one option per field, and a field may be left empty. The design chat fills existing events, or shows a field on a layout, only when asked. Removing a field does not rewrite existing events, because there are many of them. New events do not gain the removed field, and a stored id that is no longer an option is ignored. A separate mode for this was rejected, as were rewriting every event on removal and filling or showing a field without being asked. These event fields are not the structured values that the home, room, gallery, and allies layouts read.
