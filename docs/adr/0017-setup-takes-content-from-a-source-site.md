# Setup asks for a source site and can take its content, in bulk, by rule

Setup asks whether the person already has a website. If so, it asks what to take (look, texts, pictures) and how much: the main pages, or every page and post. The main pages go into the setup proposal as a first pass. A full import runs after the proposal is accepted, as its own reply, so one Undo takes it back. An `import_pages` tool does it without a model call per page: the agent reads a few pages and sets the mapping once (which kind of page goes to which layout and which slot receives what), and the tool applies it to every page, saves the pictures, and reports the pages that did not fit.

This reverses the part of 0009 that said a full archive import is not required to start. It was left out because the next housing project is not a copy of the old one; the person now chooses it, per project. The alternative, reading and writing each page in the chat, was rejected because one long import turn cost about 12M tokens and hit output limits in production. A rule-based mapping is cheap and covers any number of pages, at the price that an odd page lands in a plain article layout and needs a later hand edit.

Boundaries: only languages the new site has and the source offers are taken, and nothing is translated. A run takes at most 200 pages and 300 pictures and lists what it skipped; `content/sources.yml` records which source address became which page, so a second run continues and updates instead of duplicating. The imprint is taken as text; the privacy page is not, because it describes the old site's tracking and external hosts, which the new site must not have (0015). The menu follows the sections the person chose, not the source's menu. Words and pictures are taken only from a source site the person names for that purpose.
