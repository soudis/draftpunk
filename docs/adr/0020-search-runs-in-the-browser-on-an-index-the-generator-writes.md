# The search runs in the visitor's browser, on an index the generator writes

The public site is static (0002), so a search cannot ask a server. The generator writes `search-index.<language>.json` with every page, post and event of that language (title, address, kind, the words of the page, the day of a post), and a generated layout `search` (page `/suche/`, like the calendar at `/kalender/`) holds a small script without a library that loads the index and finds words, ignoring capitals, accents and ß. The starter header has a field that opens `/suche/?q=…`. The page is marked noindex and left out of the sitemap, but not blocked in robots.txt, so search engines can see the mark. A site made before the search has no `search` layout, and then gets no page and no index.

Rejected: a search endpoint on the editor host, which would make the public site depend on a server and break the rule that a visitor's browser contacts no one else; and a hosted search service, which would send visitors' searches to a third party. The price: the whole index is sent to a visitor who searches, so each page keeps only its first 400 to 1,500 characters (fewer when the site is bigger), and a site of several thousand pages would need an index split into parts, which is not built.
