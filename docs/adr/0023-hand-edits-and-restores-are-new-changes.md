# A hand edit and a restore are new changes on top of the draft, and a content file is edited as a form

The editor gained a content browser and a history next to the chat. A person saves one content file from a form, and the server writes the file, builds the site and commits only that file with a sentence for a message ("Updated the page Kontakt"), authored by the person and marked with a `Draftpunk-Kind` trailer. The history reads the draft branch and marks each change as a chat reply, an edit, a publish, a restore, an undo, or a picture. Older commits have no trailer and are told apart by their message. Restore puts the draft's files (all of them, or one file) back to how an earlier change had them and commits that as a new change, so a restore can itself be restored. A change can also be undone with `git revert` when no later change edited the same files, the rule the chat Undo already used. A save carries a hash of the file as it was opened and is refused when the file has changed since, so it never writes over a reply or a colleague.

Rejected: `reset --hard` to an earlier change, which would drop other people's later work from a draft that is shared and would leave the Undo buttons of their chats pointing at commits that no longer exist; and editing the raw YAML, which is faster to build but leaves indentation mistakes to people who write housing-project news. The form is built from the layout's slot schema, so a file it saves always fits its layout. The price is a form builder that has to know every slot type, and that content created or deleted by hand, or a page moved to another layout, still goes through the chat.
